# Milestone v1.3: Betting Strategy Optimization

**Status:** ✅ SHIPPED 2026-05-05
**Phases:** 11-13
**Total Plans:** 7

## Overview

バックテストROI 91.6% → 100%超えを達成するため、ベット選択の厳格化とステークサイジング最適化を実装。OddsBandFilter/EV_lower/RegimeDetector skipによる3段階フィルター、Kelly基準レジーム別サイジング、DD再設計・パラメータ外部化・Optuna TPE最適化を統合。

## Phases

### Phase 11: Bet Selection Filters

**Goal**: 低信頼ベット・不安定レジーム・赤字オッズバンドを自動除外し、バックテストのベット品質が向上する
**Depends on**: Phase 10 (v1.2 complete)
**Plans**: 2 plans

Plans:

- [x] 11-01: OddsBandFilter クラス + EV_lower フィルター + RegimeDetector skip=True (BSEL-01, BSEL-03)
- [x] 11-02: Engine統合 (COLLAPSED skip + OddsBandFilter + counters + guard) + レポート除外統計 (BSEL-01, BSEL-02, BSEL-03)

**Details:**
- OddsBandFilter クラス: calibrate() でトレーニング期間ROI計算、filter() で除外バンド候補を除去
- EV_lower_win_corrected >= 1.0 フィルター in get_win_candidates()
- RegimeDetector COLLAPSED 分岐に skip=True を追加
- BacktestResult dataclass に除外フィールド追加 (n_collapsed_skipped, n_ev_excluded, n_odds_band_excluded, exclusion_stats)
- COLLAPSED regime skip を recent_stats_list 蓄積後に実行 (Pitfall 3 対策)
- Bet count guard WARNING (< 1000 bets/year)
- レポート generate() + save_ai_diagnostics() に除外統計セクション追加

### Phase 12: Stake Sizing Enhancement

**Goal**: レジーム状態に応じたKelly分数とEV比例乗算器により、高確信ベットに重点配分された賭け金が算出される
**Depends on**: Phase 11
**Plans**: 2 plans

Plans:

- [x] 12-01: StakeCalculator コンストラクタ注入リファクタリング + apply_ev_scaling() 実装 (SIZE-01, SIZE-02)
- [x] 12-02: RegimeDetector/MetaSwitcher パラメータ追加 + Kelly→EV乗算→DD パイプライン統合 (SIZE-01, SIZE-02)

**Details:**
- StakeCalculator: FRACTIONAL_KELLY/KELLY_FRACTION_CAP をクラス属性から __init__ 引数に移行
- apply_ev_scaling(stake, ev) メソッド追加: scale = min(ev / target_ev, max_scale)
- RegimeDetector: 3レジーム dict に fractional_kelly を追加 (AGGRESSIVE: 0.50, CONSERVATIVE: 0.25, COLLAPSED: 0.00)
- MetaSwitcher: _default_params() の5箇所の値乖離を解消
- engine.py: レースループ内の regime_params 取得直後に fractional_kelly 注入
- race_predictor.py: select_bets() winパスで Kelly->EV乗算->DD パイプラインに変更

### Phase 13: Risk Calibration & Parameter Optimization

**Goal**: WIN向中率10%に最適化されたDD制御が動作し、ルックアヘッドバイアスを防いだ上で全戦略パラメータが最適化される
**Depends on**: Phase 12
**Plans**: 3 plans

Plans:

- [x] 13-01: DrawdownController再設計 (ROI除去・3段階制御・コンストラクタ注入・ヒステリシス) (RISK-01)
- [x] 13-02: RegimeDetector外部化 + ParameterFreezeProtocol JSON manifest (VAL-01)
- [x] 13-03: StrategyOptimizer (Optuna TPE最適化・軽量WFループ・CLI) (VAL-02)

**Details:**
- DDConfig dataclass: 9パラメータ + __post_init__閾値整合性検証
- DrawdownController完全再設計: ROI計算コード(numpy依存含む)を完全除去
- RecoveryState enum: RECOVERING -> STOP に変更(3値のみ)
- ヒステリシス(min_stay_races)による状態遷移発振防止
- 段階的リカバリ: STOP -> REDUCED -> NORMAL (即時復帰禁止)
- RegimeDetector: override_params で外部上書き可能に (Optuna最適化の前提)
- ParameterFreezeProtocol: save/verify/load_strategy_manifest (JSON + SHA256改ざん検知)
- StrategyOptimizer: Optuna TPE ~14次元探索空間 (レジーム別6 + DD制御5 + EVスケーリング2 + OddsBandFilter1)
- Walk-forward 2fold評価 + MedianPruner
- CLIスクリプト run_strategy_optimization.py

## Milestone Summary

**Key Decisions:**
- EV_lower NaN フォールバック: fillna(1.0) で >= 1.0 チェックを通す (既存のedge>0のみで判定)
- OddsBandFilter バンド境界は report.py の _band_stats と完全に同一
- DD% only for DD control: WIN的中率10%環境ではROIがノイジーすぎる
- ヒステリシスblocked時も_races_in_stateをインクリメント(永久ブロック回避)
- WalkForwardCV不使用: pipeline.run()が必須で変更リスク高のため独自軽量WFループ
- _run_single_backtest()は具象実装(NotImplementedErrorではなくModelLoader+BacktestEngine直接)
- JSON manifest: sort_keys=True + indent=2 で deterministic SHA256保証

**Issues Resolved:**
- OddsBandFilter odds=0の"30.0+"バンド誤分類を修正
- EV exclusion countがrace_predictorからengineに伝播されない問題を修正
- DrawdownControllerのpeak_bankroll <= 0でZeroDivisionErrorを修正
- _serializeのexcept句を広げて全pickle例外を捕捉
- RegimeDetectorProtocolのcallable型をCallable[[], bool]に修正

**Issues Deferred:**
- バックテストROI検証(run_backtest.py実行、PostgreSQL環境必要)
- Look-ahead bias risk in parameter optimization — walk-forward validation required
- Regime detector oscillation risk — hysteresis counter may need adjustment

**Technical Debt Incurred:**
- run_backtest.py の training_bet_history 受け渡しは今後の改善対象
- ruff F841/F401 の既存エラーが数箇所残存(今回の変更ではない)
- OddsBandFilter は betting_target='win' の場合のみ初期化(place/wideは対象外)
