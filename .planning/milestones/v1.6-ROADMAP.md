# Milestone v1.6: Feature Engineering Overhaul

**Status:** Shipped 2026-05-17

**Total Plans:** 14

## Overview

CQRに頼らず、特徴量の質と量を根本から見直し、バックテストROI 100%超えを目指す。POST_RACE漏洩排除、特徴量監査基盤構築、EveryDB2未活用データからの新特徴量抽出、交互作用項・ターゲットエンコーディング導入を経て、ROI 85.7% (+1.3pp改善) を達成。100%目標は未達。

## Milestone Summary

**Key Decisions:**

- POST_RACE_COLS whitelist approach: blacklistからwhitelistへの切り替えで漏洩リスクを排除
- Tier分類のpercentile-based threshold: モデルごとに適応的な閾値設定
- 12特徴量追加は安全: LightGBMが不要特徴量をgain=0にするためROI悪化なし
- DataKubun=3優先 + =2フォールバック: 情報量最大の直前予想を主ソース
- Stage1にTE追加せず: TE target == Stage1 targetでOOFリークの可能性を回避
- Expanding window TE: AbilityModel.train_oof()と同一fold境界で安全性保証

**Issues Resolved:**

- POST_RACE漏洩(build_all()出力にPOST_RACE_COLS混入)を完全排除
- CQR blacklistの脆弱性をwhitelist FEATURE_COLSで解消
- feature cache stale問題をcode hash無効化で解決
- BacktestEngine horse-level特徴量mergeキー不整合を修正(4連続fix)
- 推論パスに欠落していた6特徴量(stage2 relative + target encoding)を追加

**Issues Deferred:**

- WF検証スクリプトの実際の実行(PostgreSQL環境必要、~4時間)
- Human UAT 5項目(ROI検証 + EV除外確認 + Optuna確認 + seed確認 + レポート確認)
- バックテストROI検証(strategy_manifest.json未使用での結果)
- 3件のtest_training_pipeline.py既知失敗(RecordFeatures.compute mock問題)
- n_taisyogata_mining/n_sale/n_banusiテーブルからの特徴量抽出(未検証)

**Technical Debt Incurred:**

- test_win_feature_analysis.pyのoriginal_allハードコードリストがFEATURE_COLS変更のたびに手動更新が必要
- test_training_pipeline.pyの3件既知失敗が未修正(RecordFeatures.compute mockのduplicate race_ids)
- ETL実行(run_etl.py --tables n_mining n_sanku n_record)がユーザーローカル手動実行必要
