    Cross-reference chain for dam features:
    1. entry_df has kettonum for each racing horse
    2. Load sanku.parquet -> filter where KettoNum matches racing horse's kettonum -> get MNum (dam's breeding number)
    3. Load sanku.parquet again -> find all entries where MNum == dam's MNum -> those are dam's offspring
    4. For each offspring, get career stats from horse_career_stats.parquet
    5. Aggregate: total offspring wins / total offspring starts = dam_wr (Beta smoothed)
    6. Also extract BreederCode from sanku for each offspring to compute breeder_strength

    Implementation:
    - __init__(store: ParquetStore): self.store, self._sanku_cache, self._career_cache
    - _load_sanku() -> pd.DataFrame: load and cache sanku.parquet
    - _load_career_stats() -> pd.DataFrame: load via db.readers.load_career_stats(store)
    - compute(entry_df: pd.DataFrame) -> pd.DataFrame:
      1. Get unique kettonum values from entry_df
      2. Load sanku, map kettonum -> MNum (dam breeding number). Use sanku.set_index("kettonum")["mnum"] if column names are lowercase after ETL.
      3. For each unique dam MNum, find all offspring: sanku[sanku["mnum"] == dam_mnum]["kettonum"]
      4. Load career_stats, filter to offspring kettonums
      5. Aggregate per dam: sum of wins, sum of starts (latest career row per horse)
      6. Compute dam_wr: Beta(1,10) smoothed = (total_wins + 1) / (total_starts + 11)
      7. Compute dam_surface_wr: same but using turf-specific stats (turf_wins / turf_starts)
      8. Compute dam_prize_log: log(1 + mean offspring total prize)
      9. Compute breeder_strength: For each dam, collect BreederCode from sanku for all offspring. Count unique breeders: len(set(breeder_codes)). Then log(1 + unique_breeder_count). This captures how widely a dam's offspring are valued -- breeders who produce many horses from the same dam indicate strong breeding reputation.
      10. Map dam features back to entry_df via kettonum -> dam_mnum -> dam_features
      11. Return result[["race_id", "umaban"] + FEATURE_COLS]

    Important: Column names from Parquet may be lowercase after ETL. Check actual schema after ETL. Use .columns.str.lower() normalization if needed.

    **File 1: src/features/record_features.py**

    Create RecordFeatures class:

    FEATURE_COLS: list[str] = ["course_record_time"]

    class RecordFeatures:
        def __init__(self, store: ParquetStore) -> None:
            self.store = store
            self._record_cache: pd.DataFrame | None = None

        def _load_records(self) -> pd.DataFrame:
            if self._record_cache is None:
                if self.store.exists("raw", "record"):
                    self._record_cache = self.store.read("raw", "record")
                else:
                    self._record_cache = pd.DataFrame()
            return self._record_cache

        def compute(race_df: pd.DataFrame) -> pd.DataFrame:
            MERGE STRATEGY:
            1. race_df MUST contain columns: race_id, jyocd, trackcd, kyori
            2. Load record.parquet
            3. Filter RecInfoKubun == "1" (course records only)
            4. For each unique (jyocd, trackcd, kyori) combination in race_df:
               a. Find all matching records in record_df
               b. Select the most recent: sort_values("makedate").groupby(["jyocd", "trackcd", "kyori"]).last()
               c. This produces exactly one course_record_time per unique (jyocd, trackcd, kyori)
            5. Parse RecTime (varchar) to float seconds:
               - RecTime format is "m:ss.s" stored as 4-char varchar
               - char 0 = minutes digit, chars 1-3 = ss.s (e.g. "1553" = 1 min 55.3 sec = 115.3 sec)
               - Handle edge case: "0550" = 0 min 55.0 sec = 55.0 sec
               - Handle edge case: "0000" or invalid -> NaN
            6. Create a lookup DataFrame: one row per unique (jyocd, trackcd, kyori) with course_record_time
            7. Merge back to race_df on (jyocd, trackcd, kyori) -> adds course_record_time to every race row
            8. Return result[["race_id"] + FEATURE_COLS]

            The key insight: course_record_time is a RACE-LEVEL feature (same value for all horses in the same race), because it depends only on (jyocd, trackcd, kyori) which is constant within a race. All horses in the same race get the same course_record_time. LightGBM will learn to use it as a race-difficulty baseline.
