```python
def compute_env_adaptability(
    kakuteijyuni_arr: np.ndarray,
    syussotosu_arr: np.ndarray,
    distance_bin_arr: np.ndarray,
    surface_arr: np.ndarray,
    track_condition_arr: np.ndarray,
    current_distance_bin: str,
    current_surface: str,
    current_track_condition: float,
) -> dict[str, float]:
    """環境変化適性9特徴量を計算。

    3変化(距離/サーフェス/馬場状態) x 3サブ特徴量(平均着順/勝率/経験回数)。
    変更が検出された場合のみ該当変化の統計を計算。変更な場合はNaN。

    Returns dict with keys:
        dist_change_avg_pos, dist_change_win_rate, dist_change_exp_count,
        surf_change_avg_pos, surf_change_win_rate, surf_change_exp_count,
        cond_change_avg_pos, cond_change_win_rate, cond_change_exp_count
    """
```

ロジック (per D-10, D-11):
1. 結果dictの全キーをNaNで初期化
2. 各変更タイプについて、ヘルパー関数 `_compute_change_stats` を呼び出す:
   ```python
   def _compute_change_stats(
       change_detected: bool,
       match_mask: np.ndarray,
       kakuteijyuni: np.ndarray,
       syussotosu: np.ndarray,
       prefix: str,
   ) -> dict[str, float]:
       """変更検出時に対象過去走の統計を計算"""
   ```
3. **距離変更:** `current_distance_bin != 最後の過去走のdistance_bin`:
   - 過去走のうち `distance_bin == current_distance_bin` の走を抽出
   - `_compute_change_stats(True, match_mask, ...)` で avg_pos, win_rate, exp_count を計算
   - 距離bin単位(sprint/mile/intermediate/long)で集計 (per D-11)
4. **サーフェス変更:** `current_surface != 最後の過去走のsurface`:
   - 過去走のうち `surface == current_surface` の走を抽出
   - 同様に avg_pos, win_rate, exp_count を計算
5. **馬場状態変更:** `current_track_condition != 最後の過去走のtrack_condition`:
   - 過去走のうち `track_condition == current_track_condition` の走を抽出
   - 馬場は広カテゴリ(track_condition_codeの値そのまま)で集計 (per D-11)
   - 同様に avg_pos, win_rate, exp_count を計算
6. `_compute_change_stats` 内:
   - `match_mask.any()` がFalse → 全てNaN返す (経験回数0)
   - avg_pos: 該当走の正規化着順 `(pos-1)/(size-1)` の平均。低いほど良い
   - win_rate: 該当走のうち `kakuteijyuni == 1` の割合
   - exp_count: 該当走数 (float)
7. 各変更で変更が検出されなかった場合(`current == last`)はNaNのまま (計算対象外)

**変更箇所4: per-horseループ内 — フォーム改善率 (クラストラジェクトリの直後)**

z-score配列が必要なため、haron_zscore_trend計算 (L759付近) の後にtime_improvement_rateとposition_improvement_rateを計算。ただし、haron_zscore_trendの計算はexpanding_stats依存で複雑なため、代わりに`horse_arrs["harontimel3"]`配列と`horse_arrs["distance_bin"]`配列から直接z-scoreを計算するのではなく、既存の`_compute_haron_stats`の戻り値を利用する。

実際の実装では、compute_form_improvement_rate には生のharontimel3配列を渡すのではなく、distance_bin別のz-scoreが必要。しかしD-09では「クラス調整済みz-score(harontimel5_zscore)のEMA改善率」とある。horse_arrsにはharontimel5_zscoreの計算済み値は含まれない（compute()内で計算される一時変数）。

したがって、実際の実装方針:
- `time_improvement_rate` には生の `harontimel3` 配列を渡す。`compute_form_improvement_rate` 内でEMA改善率を計算（z-score化は不要。EMA改善率が直近の改善傾向を捉える）
- `position_improvement_rate` には `kakuteijyuni` と `syussotosu` を渡す
- 配列は `valid_mask[start:idx]` でフィルタしたものを使用

