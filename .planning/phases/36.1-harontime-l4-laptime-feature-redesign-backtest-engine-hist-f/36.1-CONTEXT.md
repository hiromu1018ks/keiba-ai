# Phase 36.1: HaronTime L4/LapTime Feature Redesign - Context

**Gathered:** 2026-05-20
**Status:** Ready for planning
**Source:** Developer design session (bug analysis + feature redesign)

<domain>
## Phase Boundary

Phase 36 の設計バグ（harontimel4 データソース誤り）を修正し、レースレベルデータを馬特徴量として有効活用する3層アーキテクチャに再設計する。同時に backtest engine の hist_features 欠落バグを修正する。

### 根本原因（3つ）

**原因1: harontimel4 データソース誤り**
- HaronTimeL4（後4ハロン）は n_race（レースレベル）と n_uma_race（馬レベル）の両方にカラムが存在
- n_uma_race の harontimel4: 全852,216行が"000"センチネル → JRA-VAN DataLab が馬個別の後4Fタイムを未提供
- n_race の harontimel4: 38,843件の有効データあり（先頭馬のタイム = レースレベル）
- n_uma_race の harontimel3: 有効データあり（馬個別の後3Fタイム）。既存機能として正常動作
- Phase 36 の compute() の race_cols_all（line 453-463）に harontimel4 が含まれていない → entries 側（全NaN）から読んでいる

**原因2: LapTime pace 特徴量の意味論問題**
- LapTime1-25 は n_race テーブルにのみ存在（先頭馬のラップタイム = レースペース）
- HorseHistoryFeatures で馬の過去レースにマージして計算 → 「その馬が出走したレースの先頭馬のペース」
- AI提案は「概念エラーだから削除」だが、これは**ペースコンテキストとして有効**（削除せずリフレームする）

**原因3: テストデータで Phase 36 全22特徴量が欠落**
- 学習時: HorseHistoryFeatures の結果が horse_features.parquet に統合保存 → 22特徴量が学習データに含まれる
- テスト時（BacktestEngine）: build_all() の出力のみが parquet に保存。hist_df_all はメモリ上で保持されるが parquet に保存されない
- モデルは22特徴量を期待しているがテストデータに存在しない → 全てNaN → 投票数減少（2,463→888）と ROI 悪化（97.8%→78.7%）

</domain>

<decisions>
## Implementation Decisions

### Tier 1: クロスレベル派生特徴量（NEW — 最も価値が高い）

- D-01: `closing_speed_ratio = harontimel3_horse / harontimel4_race`
  - 同一レース内でも馬ごとに異なる値（L3が個人、L4が共通）
  - レースペースの影響を自動補正
  - 派生: closing_speed_ratio_avg, _zscore, _trend（3特徴量）
  - EMA halflife=3（既存パターンと同一）

- D-02: `haron_race_gap = harontimel3_horse - harontimel4_race * 0.75`
  - L4を3F区間にスケール変換した期待値と個人のL3の差分（残差）
  - 負 = 速い末脚（レース平均より上）
  - 派生: haron_race_gap_avg, _zscore, _trend（3特徴量）

- D-03: `pace_adjusted_finish = norm_finish * pace_ratio`
  - norm_finish = (着順-1)/(頭数-1)（既存のnorm_finish_logit_avgと同じ正規化）
  - ペースコンテキストを考慮した着順評価
  - 派生: pace_adj_finish_avg（1特徴量）

### Tier 2: ペースコンテキスト特徴量（既存リフレーム — 削除しない）

- D-04: pace_ratio_avg/zscore/trend は保持。意味を「この馬が経験したレースの上がりペース傾向」として再定義
  - 高いクラスのレースほど上がりが速い（pace_ratio低）→ クラスの代理変数
  - LightGBM が harontimel5_avg（個人末脚）と pace_ratio_avg（環境ペース）の交互作用を自動発見可能

- D-05: pace_early/mid/late_avg は保持
  - 「この馬が出走するレースのペース構造」= 脚質の代理変数
  - 逃げ馬は前傾ペースのレースに多く出走 → early が速い傾向

### Tier 3: 個人末脚特徴量（既存 — harontimel4 部分のみ修正）

- D-06: harontimel3_avg/zscore/trend はそのまま保持（正常動作中）

- D-07: harontime_last3f 統合列は L3 ベースに統一
  - L4 はレースレベルなので距離閾値による L4/L3 切替は無意味
  - harontime_last3f_avg/zscore/trend は常に harontimel3（個人）ベースで計算
  - 距離閾値 DISTANCE_THRESHOLD の分岐ロジックを撤廃

- D-08: harontimel4_avg/zscore/trend を closing_speed_ratio に置換（D-01）
  - 旧 harontimel4_avg → closing_speed_ratio_avg
  - 旧 harontimel4_zscore → closing_speed_ratio_zscore
  - 旧 harontimel4_trend → closing_speed_ratio_trend
  - 旧 harontimel4_avg_race_rank → closing_speed_ratio_race_rank

### データソース修正

- D-09: compute() の race_cols_all（line 453-463）に "harontimel4" を追加
  - races.parquet からレースレベル L4 を取得
  - past_df マージで entries 側（全NaN）ではなく races 側（38,843件有効）から供給
  - LapTime pace 処理（line 731-815）と同じパターン

- D-10: cols_horse（line 524-544）の "harontimel4" はそのまま（past_df に含まれるようになる）

### Backtest Engine 修正

- D-11: engine.py で predict() 前に hist_features を feat_df にマージ
  - hist_df_all の列が backtest parquet に含まれるようにする
  - これによりテストデータに22特徴量が反映される

<specifics>
## Specific Ideas

### closing_speed_ratio の計算例

```
                 harontimel3   harontimel4_race   ratio
馬A (レース1):     34.5           46.0          0.750  ← レースペースに対して速い
馬B (レース1):     36.2           46.0          0.787  ← レースペースに対して遅い
馬A (レース2):     33.8           44.5          0.759
馬A (レース3):     35.1           47.2          0.744

closing_speed_ratio_avg (EMA) = 0.751 → "末脚がレースペースを上回る馬"
```

### haron_race_gap の計算例

```
期待値: L4 × 0.75 = レースのL4を3F区間にスケール変換
差分 = 個人のL3 − 期待値

馬A: 34.5 − 46.0×0.75 = 34.5 − 34.5 =  0.0  (平均的)
馬B: 36.2 − 46.0×0.75 = 36.2 − 34.5 = +1.7  (遅い)
馬C: 33.1 − 46.0×0.75 = 33.1 − 34.5 = -1.4  (速い = 強い末脚)
```

### pace_adjusted_finish の計算例

```
norm_finish = (着順 - 1) / (頭数 - 1)
pace_adjusted = norm_finish × pace_ratio

速い上がりレース (pace_ratio < 1.0) で好着順 → 印象的
遅い上がりレース (pace_ratio > 1.0) で低迷 → 問題視
```

### LapTime 保持の理由

```
馬A: 過去5走のL4 = [46.2, 45.8, 47.1, 46.0, 45.5] → avg=46.1 (高速レース経験豊富)
馬B: 過去5走のL4 = [48.5, 49.1, 47.8, 48.0, 49.5] → avg=48.6 (低レベルレース中心)

同一レースのAとB: 同じL4値。しかし「経験ペースの平均」は明確に異なる。
→ pace_late_avg は「この馬がどのレベルのレースに出走しているか」を反映 = クラスの代理変数
```

</specifics>
