### Pattern 1: Cross-Level Derived Feature (closing_index_avg パターン)
**What:** レースレベル値と馬個人値の組み合わせから派生特徴量を計算
**When to use:** 同一レース内で全馬に共通する値（レースペース等）と馬個人の値の比率/差分
**Example:**
```python
# Source: horse_history_features.py line 1230-1244 (closing_index_avg)
# 成功パターン: 4コーナー通過順位(レース) と 着順(個人) の差分
if _has_jyuni4c and n_past > 0:
    c4_raw = horse_arrs["jyuni4c"][valid_mask][start:idx].astype(float)
    kj_raw = horse_arrs["kakuteijyuni"][valid_mask][start:idx].astype(float)
    sy_raw = horse_arrs["syussotosu"][valid_mask][start:idx].astype(float)
    valid_ci = ~np.isnan(c4_raw) & ~np.isnan(kj_raw) & ~np.isnan(sy_raw) & (sy_raw > 1)
    if valid_ci.any():
        norm_4c = (c4_raw[valid_ci] - 1) / (sy_raw[valid_ci] - 1)
        norm_finish = (kj_raw[valid_ci] - 1) / (sy_raw[valid_ci] - 1)
        closing_indices = norm_4c - norm_finish
        closing_index_avg = float(closing_indices[-self._n_past:].mean())
```

### Pattern 3: EMA Weighted Average (halflife=3)
**What:** 指数移動平均で直近のレースに重み付け
**When to use:** 全ての avg 特徴量 (closing_speed_ratio_avg, haron_race_gap_avg 等)
**Example:**
```python
# Source: horse_history_features.py line 905-919 (harontimel5_avg)
halflife = 3
decay = np.log(2) / halflife  # ~0.231
n_ht = len(ht_valid)
weights = (1 - decay) ** np.arange(n_ht)
weights = weights[::-1]  # index 0 = newest (highest weight)
weights = weights / weights.sum()
harontimel5_avg = float(np.sum(ht_valid * weights))
```

### Anti-Patterns to Avoid
- **レースレベル値をそのまま馬特徴量に使わない:** harontimel4_race を直接 avg/zscore に使うのは誤り（同一レース内の全馬が同じ値になる）。必ず個人値 (L3) との比率/差分に変換する
- **entries 側の L4 を使わない:** n_uma_race の harontimel4 は全852,216行が"000"センチネル。必ず n_race (races.parquet) から取得する
- **predict() に渡した hist_features を feat_df に反映させない:** predict() 内部で merge しても外側の feat_df には反映されない。事前にマージする

## Common Pitfalls

### Pitfall 1: harontimel4 の NaN カバレッジ (56%)
**What goes wrong:** closing_speed_ratio = L3 / L4 は L3 と L4 の両方が有効なレースのみ計算可能。L4 は56%カバレッジのため、closing_speed_ratio のカバレッジは L3カバレッジ x L4カバレッジ に低下する可能性がある。
**Why it happens:** JRA-VAN DataLab が全レースで L4 を提供していない
**How to avoid:** LightGBM は NaN をネイティブ処理可能。NaN をそのまま渡し、モデルが学習する。falling back はしない（情報が薄まる）
**Warning signs:** closing_speed_ratio_avg が70%以上NaN → 特徴量として寄与しない可能性

### Pitfall 2: closing_speed_ratio の expanding_stats キー衝突
**What goes wrong:** 既存の expanding_stats (harontimel3 用) と expanding_stats_hl4 (harontimel4 用) とは別のキー。新規 closing_speed_ratio 用の expanding_stats も別 dict にする必要がある。
**Why it happens:** 同一 dict に同じ group key ("sprint", "turf", "1") が存在すると、L3 stats が closing_speed_ratio stats を上書きする
**How to avoid:** expanding_stats_csr (closing_speed_ratio用) と expanding_stats_hrg (haron_race_gap用) を別 dict で管理
**Warning signs:** zscore 値が L3 zscore と同一 → キー衝突の兆候

### Pitfall 3: Backtest engine での二重マージ
**What goes wrong:** D-11 で feat_df に hist_df_all を事前マージした後、predict() に hist_features を渡すと二重マージが発生し、_x/_y サフィックス列が生成される
**Why it happens:** predict() は hist_features が non-None の場合、内部で merge を実行する
**How to avoid:** D-11 マージ後は predict() に hist_features=None を渡す。または hist_df_race を predict() に渡す代わりに、feat_df に既に含まれていることを前提とする
**Warning signs:** result_df に _x/_y サフィックス列が現れる

### Pitfall 4: harontime_last3f の L3 ベース統一後の欠損増加
**What goes wrong:** DISTANCE_THRESHOLD (2000m) による L4/L3 切替を撤廃し L3 のみ使用すると、長距離レースで L4 が有効だった馬の unified 値が NaN になる可能性
**Why it happens:** 現在のロジックは長距離(>=2000m)では L4 を優先。これを L3 のみにすると、L3 が NaN の場合に値がなくなる
**How to avoid:** L3 は entries 側に有効データがあるため、実際にはカバレッジ低下は最小。L4 は entries 側で全NaNのため、現在のロジック自体が L3 フォールバックに依存していた
**Warning signs:** harontime_last3f_avg の NaN率が harontimel3_avg の NaN率と一致することを確認

### Pitfall 5: MODEL FEATURE_COLS の一貫性
**What goes wrong:** 一部モデルだけに新特徴量を追加すると、特徴量リストの不整合が発生する
**Why it happens:** 8+ のモデルファイルに分散して FEATURE_COLS が定義されている
**How to avoid:** 全モデルファイルを横断的に更新。一覧: stage1_ability_model, two_stage_return_model (Win/Place), ev_correction_model, market_model, place_ability_model, regime_detector, wide_two_stage_model, race_predictor._race_rank_cols
**Warning signs:** テストで "Missing feature columns filled with NaN" ログが新特徴量名で出力される

### D-01: closing_speed_ratio の計算 (per-horse loop 内)
```python
# Pattern: closing_index_avg (line 1230-1244) を参照
# 個人L3 と 共通L4 の比率を計算

closing_speed_ratio_avg: float = float("nan")
closing_speed_ratio_zscore: float = float("nan")
closing_speed_ratio_trend: float = float("nan")

if _has_harontimel3 and _has_harontimel4 and n_past > 0:
    l3_raw = horse_arrs["harontimel3"][valid_mask][start:idx].astype(float)
    l4_raw = horse_arrs["harontimel4"][valid_mask][start:idx].astype(float)  # race-level L4 from races_hist

    # closing_speed_ratio = L3_horse / L4_race (per past race)
    valid_csr = ~np.isnan(l3_raw) & ~np.isnan(l4_raw) & (l4_raw > 0)
    if valid_csr.any():
        csr_values = l3_raw[valid_csr] / l4_raw[valid_csr]

        # EMA avg (halflife=3)
        halflife_csr = 3
        decay_csr = np.log(2) / halflife_csr
        n_csr = len(csr_values)
        weights_csr = (1 - decay_csr) ** np.arange(n_csr)
        weights_csr = weights_csr[::-1]
        weights_csr = weights_csr / weights_csr.sum()
        closing_speed_ratio_avg = float(np.sum(csr_values * weights_csr))

        # trend (last 3 linear regression)
        csr_trend = csr_values[-3:] if len(csr_values) >= 3 else csr_values
        if len(csr_trend) >= 2:
            x_csr = np.arange(len(csr_trend), dtype=float)
            closing_speed_ratio_trend = float(np.polyfit(x_csr, csr_trend, 1)[0])
```
