Per D-09 (independent evaluator), D-10 (GatePolicy dataclass), D-11 (specific gate conditions), D-12 (report only, no model changes), D-13 (auto-deploy deferred):

Create src/backtest/deployment_gates.py:

1. Import json, logging, hashlib, Path from pathlib. Use `from __future__ import annotations`. Import dataclass with frozen=True from dataclasses. Import Any for type hints.

2. Define GatePolicy as frozen dataclass with fields per D-10 and D-11:
   - brier_tolerance: float = 1e-6
   - logloss_tolerance: float = 1e-6
   - ece_tolerance: float = 1e-6
   - bet_count_ratio_threshold: float = 0.95
   - require_oof_pass: bool = True
   - require_audit_pass: bool = True
   - require_manifest_complete: bool = True

3. Define module constant: DEFAULT_GATE_POLICY = GatePolicy()

4. Define GateConditionResult dataclass (not frozen -- mutable for construction convenience):
   - condition_name: str
   - status: str  # "PASS", "FAIL", "WARN", "SKIP"
   - message: str
   - details: dict[str, Any] = field(default_factory=dict)

5. Define GateEvaluationResult dataclass:
   - overall_status: str  # "PASS", "FAIL", "WARN"
   - policy: GatePolicy
   - conditions: list[GateConditionResult]
   - report_metrics: dict[str, Any]  # non-gate metrics (selection_agreement, ROI) for reporting only per D-11
   - generated_at: str  # ISO timestamp

6. Define DeploymentGateEvaluator class with __init__(self, policy: GatePolicy | None = None) storing self.policy = policy or DEFAULT_GATE_POLICY.

7. Implement evaluate(self, result_path: str | Path, manifest_path: str | Path | None = None) -> GateEvaluationResult:
   a. Load and parse result_path JSON. Raise FileNotFoundError if missing.
   b. If manifest_path provided, load and parse it. If missing but require_manifest_complete, add FAIL condition.
   c. Identify baseline and shadow variant names from manifest flag_states: variant with enable_market_aware_calibrator=False is baseline, variant with enable_market_aware_calibrator=True is shadow. Per RESEARCH Pitfall 4 (handle any variant naming, not hardcoded "baseline"/"shadow").
   d. For each fold year in result["folds"]: evaluate probability quality gates (brier, logloss, ECE) comparing shadow vs baseline with tolerance. Per D-11 and RESEARCH Pitfall 5 (floating-point tolerance: shadow <= baseline + tolerance).
   e. Evaluate overall probability quality gates from result["overall"]["metrics"].
   f. Evaluate bet count preservation: shadow_bet_count >= baseline_bet_count * bet_count_ratio_threshold per D-11.
   g. Evaluate actual/predicted ratio: WARN (not FAIL) if shadow worse than baseline per D-11.
   h. If manifest exists: evaluate artifact reproducibility (SHA256 from manifest, artifacts section completeness). Per D-11.
   i. If require_oof_pass is True: add diagnostic gate for OOF health (check placeholder -- in production this would call OOFHealthValidator; for structure, add SKIP with message "OOF validation requires manual run" since this is CI-independent per D-05).
   j. If require_audit_pass is True: add diagnostic gate for feature routing audit (similar SKIP placeholder).
   k. Collect non-gate metrics (selection_agreement, ROI) into report_metrics dict per D-11 ("non-gate, report only").
   l. Determine overall_status: FAIL if any condition FAIL, WARN if any WARN but no FAIL, PASS if all PASS.
   m. Return GateEvaluationResult.

8. Implement to_json(result: GateEvaluationResult, output_path: Path | None = None) -> str: serialize result to JSON. Write to output_path if provided.

9. Implement to_markdown(result: GateEvaluationResult) -> str: format result as Markdown with sections per condition.

10. CLI entry function run_deployment_gates(result_path, manifest_path, output_dir) that calls evaluate(), writes JSON + Markdown, and exits non-zero on FAIL per D-12.

2. Helper function _make_manifest_json() that constructs a minimal manifest with baseline/shadow variants and artifact SHA256 entries.

3. Class TestGatePolicy:
   - test_frozen: verify dataclass.FrozenInstanceError on attribute modification.
   - test_default_values: verify DEFAULT_GATE_POLICY has expected threshold values.

4. Class TestDeploymentGateEvaluator with methods using tmp_path fixture for file-based tests:
   - All 16 behavior tests from the <behavior> block above.
   - Each test writes the minimal JSON to tmp_path, calls evaluate(), and asserts on GateEvaluationResult conditions and overall_status.
   - Tests for probability quality failures: modify shadow metrics to be worse than baseline.
   - Tests for bet count preservation: reduce shadow bet_count below 95% of baseline.
   - Tests for artifact reproducibility: remove manifest, corrupt SHA256.
   - Tests for WARN vs FAIL: verify actual/predicted ratio produces WARN not FAIL.
   - Tests for report metrics: verify selection_agreement and ROI are in report_metrics, not in conditions.
