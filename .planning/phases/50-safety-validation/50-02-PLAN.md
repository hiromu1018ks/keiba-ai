<objective>
Run WF Fold0 NaN diagnostics, execute staged BT ROI validation, and produce per-feature IC evaluation for track condition features.

Purpose: Complete the validation pipeline from Plan 01 CI gates through BT ROI verification to IC signal assessment. This is the decisive plan that determines whether the v2.3 track condition features are deployable. Per D-01, staged BT (2025 first, then 2024+2025 if primary passes). Per D-02, at most 1 diagnostic retry for structural anomalies only.

Output: NaN report, BT results (ROI judgment), IC evaluation report.

Per D-01: Staged BT judgment. 2025 single ROI >= 97% first gate, then 2024+2025 combined >= 97% AND each year >= 90%.
Per D-02: Diagnostic retry at most once. Only structural anomalies (IC sign reversal, high NaN rate, MarketModel dominance, routing violation). ROI-only threshold adjustment prohibited.
Per D-03: Two-stage BT evaluation. Primary: --ensemble only (pure feature effect). Secondary confirmation: --min-win-ev 1.03 --min-win-odds 3.0.
Per D-07: All new features evaluated with per-feature IC, Tier-level and horse/race-level aggregation.
Per D-08: Category column (sire_x_cushion_band) evaluated separately via category-level target statistics, not forced to numeric IC.
Per D-09: IC is informational. abs(C-orthogonal IC) >= 0.005 = signal. No individual FAIL threshold.
Per D-14: Training start date NOT modified.
</objective>

  <action>
    Create scripts/run_track_condition_ic_eval.py: a per-feature IC evaluation script for track condition features.

    This differs from the existing run_ic_eval.py which evaluates model-level IC (p_win_corrected vs kakuteijyuni). This script evaluates individual feature columns against the target.

    CLI interface:
    - --oof-path: path to OOF predictions parquet (default: data/oof/oof_predictions.parquet)
    - --features-path: path to horse_features parquet (default: data/features/horse_features.parquet)
    - --output: output JSON path (default: data/audit/track_condition_ic_report.json)

    Per D-07: Evaluate all 23 track condition features. For each feature:
    1. Univariate Spearman IC: spearmanr(feature_value, kakuteijyuni) -- note kakuteijyuni is 1=1st, 2=2nd, so positive rho means feature predicts WORSE finish. Use -rho for consistency.
    2. C-orthogonal IC: Spearman(residual, kakuteijyuni) where residual = feature - OLS(feature | tanodds). This measures signal independent of market odds.
    3. NaN rate and valid sample count.
    4. Surface-stratified: compute separately for turf and dirt subsets.

    Per D-07: Tier-level aggregation:
    - T1/T2 (TRACK_CONDITION_COLS, 8 features): report mean abs(C-orthogonal IC), signal count
    - T3-04 + T4-01 + T4-03 + T4-04 (TRACK_DERIVED_COLS, 11 features): same
    - T4-02 (RACE_CONDITION_COLS, 4 features): same
    Also aggregate by horse-level (per-horse features) vs race-level (race_condition features).

    Per D-08: sire_x_cushion_band is a category column. Do NOT compute Spearman IC. Instead, compute per-category target mean (mean kakuteijyuni for each category level) and report category count, category-level variance, and Kruskal-Wallis H test p-value as the non-parametric equivalent.

    Per D-09: Classify each feature:
    - abs(C-orthogonal IC) >= 0.005: "signal"
    - abs(C-orthogonal IC) < 0.005: "weak"
    - IC is informational only -- no individual FAIL threshold.
    Flag features where IC sign reverses between surface subsets (turf vs dirt).

    Also flag features where valid sample count < 1000 (insufficient data warning).

    Output JSON structure:
    {
      "per_feature": {
        "feature_name": {
          "univariate_ic": {"rho": X, "p_value": X, "n": N},
          "c_orthogonal_ic": {"rho": X, "p_value": X, "n": N},
          "nan_rate": X,
          "signal_classification": "signal|weak",
          "by_surface": {
            "turf": {"rho": X, "n": N},
            "dirt": {"rho": X, "n": N}
          }
        }
      },
      "sire_x_cushion_band": {
        "category_count": N,
        "category_target_means": {...},
        "kruskal_wallis": {"H": X, "p_value": X}
      },
      "tier_aggregation": {
        "T1_T2": {"mean_abs_c_ic": X, "signal_count": N, "total": N},
        "T3_T4_derived": {"mean_abs_c_ic": X, "signal_count": N, "total": N},
        "T4_02_race_level": {"mean_abs_c_ic": X, "signal_count": N, "total": N}
      },
      "level_aggregation": {
        "horse_level": {"mean_abs_c_ic": X, "signal_count": N},
        "race_level": {"mean_abs_c_ic": X, "signal_count": N}
      },
      "flags": ["sign_reversal:feature_name", "low_samples:feature_name"]
    }

    Create tests/test_track_condition_ic.py with test class TestTrackConditionICEval:

    1. test_c_orthogonal_computation: Given synthetic feature + odds + target, verify C-orthogonal IC matches expected value (feature regressed out of odds, Spearman of residual vs target).

    2. test_signal_classification: abs(IC) >= 0.005 classified as "signal", below as "weak".

    3. test_category_column_separate_evaluation: sire_x_cushion_band produces Kruskal-Wallis result instead of Spearman IC.

    4. test_surface_stratification: Features evaluated separately on turf/dirt subsets when surface column exists.

    5. test_tier_aggregation: Verify mean abs C-IC is computed correctly across Tier groups.

    6. test_flag_sign_reversal: When turf IC and dirt IC have opposite signs, feature is flagged.

    Run the script against actual OOF data (if available):
    ```
    python scripts/run_track_condition_ic_eval.py --output data/audit/track_condition_ic_report.json
    ```

    Note: If OOF data does not yet contain track condition features (because training has not been re-run with new features), the script should handle gracefully and produce a report with NaN IC values and a note that retraining is required. In this case, the IC report is informational only and does not block deployment.
