    **Constructor** `__init__(self, store: ParquetStore)`:
       - Store `self.store = store`
       - Create `self._feat_engine = FeatureEngine()`
       - Create `self._submodel_mgr = SubModelManager()`

    **Public methods** per D-04:

    1. `build_for_training(self, race_df, entry_df, odds_df, *, odds_ts_df=None, preserve_columns=None, feature_version="1.0") -> FeatureBuildResult`:
       - Calls `self._build(race_df, entry_df, odds_df, odds_ts_df=odds_ts_df, preserve_columns=preserve_columns, feature_state=None, feature_version=feature_version)`
       - preserve_columns defaults to `["kakuteijyuni", "confirmed_odds"]` if None

    2. `build_for_inference(self, race_df, entry_df, odds_df, feature_state: FeatureState, *, odds_ts_df=None, feature_version="1.0") -> FeatureBuildResult`:
       - Validates `feature_state is not None`, raises ValueError if None per D-04
       - Calls `self._build(..., preserve_columns=None, feature_state=feature_state, ...)`
       - After _build: removes any POST_RACE_COLS present in the frame per D-01

    **Private method** `_build(self, race_df, entry_df, odds_df, *, odds_ts_df=None, preserve_columns=None, feature_state=None, feature_version="1.0") -> FeatureBuildResult`:
       This is the core method that replicates the _train_submodel execution order per RESEARCH Pitfall 1:

       **Phase 1 — Base features (_build_base_features):**
       a. `feat_df = self._feat_engine.build_all(race_df, entry_df, odds_df, odds_ts_df=odds_ts_df, store=self.store, preserve_columns=preserve_columns)`
       b. `feat_df = self._submodel_mgr.add_distance_band_features(feat_df)`

       **Phase 2 — Enrichment (_enrich_features) in this exact order per RESEARCH:**
       a. `HorseHistoryFeatures(store=self.store).compute(race_df, entry_df, race_ids)` → merge on [race_id, umaban]
       b. `HorseHistoryFeatures.add_race_transforms(feat_df)` — immediately after merge per Open Question 1
       c. `PaceAptitudeFeatures(store=self.store).compute_batch(feat_df)` → merge on [kettonum, race_id], all 6 columns
       d. `CourseFeatures(store=self.store).compute_batch(feat_df)` → merge on [kettonum, race_id], 2 columns
       e. `SireFeatures` — load_sire_stats(self.store), load_horses(self.store), map sire_id/bms_id from kettonum, compute_batch, assign 11 columns
       f. `DamPedigreeFeatures(store=self.store).compute(feat_df)` → merge on [race_id, umaban], 4 columns
       g. `RecordFeatures(store=self.store).compute(feat_df)` → merge on [race_id], 1 column
       h. `TrackConditionFeatures` — if feature_state provided, use its track_stats/track_month_stats. Otherwise compute from data via _compute_track_stats/_compute_track_month_stats. Then compute_race_condition_features.
       i. `compute_interaction_features(feat_df)` — 15 columns (column addition, no merge)
       j. `MiningFeatures(store=self.store).compute(feat_df)` → merge on [race_id, umaban], 4 columns
       k. `compute_relative_features(feat_df)` — 11+ columns (column addition, no merge)
       l. `JockeyContextFeatures(store=self.store).compute(entry_df)` → merge on [race_id, umaban]
       m. `TrainerContextFeatures(store=self.store).compute(entry_df)` → merge on [race_id, umaban]
       n. `JockeyTrainerComboFeatures(store=self.store).compute(entry_df)` → merge on [race_id, umaban]

       **Phase 3 — Finalization:**
       - Convert object-type numeric columns to float64 (same as _train_submodel line 1019-1024)
       - Generate FeatureManifest via `FeatureManifest.from_dataframe(feat_df, feature_version)` — this automatically excludes POST_RACE_COLS, race_id, target columns
       - Return `FeatureBuildResult(frame=feat_df, manifest=manifest)`

    **Important constraints** per D-02, D-05:
       - FeatureBuilder does NOT do DB access directly. All data loading happens through feature modules receiving self.store.
       - FeatureBuilder does NOT re-implement PIT shifting. It relies on existing modules being PIT-safe per D-05.
       - Each enrichment step follows the drop-existing-then-merge pattern from _train_submodel (drop columns that already exist, then merge new values).

    **Error handling:**
       - If any required column is missing after enrichment (e.g., race_id, umaban), raise ValueError with column name
       - If merge produces unexpected row count increase, log warning

       - Test manifest hash is deterministic for same inputs

       - Use mock ParquetStore and small synthetic DataFrames (3-5 rows, minimal columns: race_id, umaban, kettonum, surface, race_date, trackcd)
