# Phase 52 Plan 04: FeatureBuilder Gap Closure — PT スクリプト統合 + BloodlineFeatures ドキュメント

**Goal:** VERIFICATION.md の2件ギャップを解消し、SC1「BT/PT/TrainingPipeline が同じ関数を呼び出す」を完全達成する。

## Context

Phase 52 の Wave 1-3 で FeatureBuilder 基盤を構築したが、`run_paper_trading.py` の3つの実行モード (`_run_predict`, `_run_diagnose`, `_run_dry_run`) が旧来の FeatureEngine + 手動エンリッチメントを使用している。BacktestEngine.run() は既に FeatureBuilder に移行済みであり、同一パターンを適用可能。

## Gap Summary

| # | Severity | Gap | Fix |
|---|----------|-----|-----|
| GAP-1 | BLOCKER | `_run_predict`/`_run_diagnose`/`_run_dry_run` が FeatureBuilder 未使用 (各70行の手動コード) | FeatureBuilder.build_for_training() に置換 |
| GAP-2 | WARNING | `_enrich_features()` docstring に BloodlineFeatures の記載なし | docstring に Group B で実行される旨を追記 |

## Approach

### GAP-1: FeatureBuilder 採用

BacktestEngine.run() (engine.py L946-1002) の確立パターンをそのまま適用:

```
現在 (各関数 70行):
  FeatureEngine.build_all() + SubModelManager.add_distance_band_features()
  + 手動 BloodlineFeatures/SireFeatures/PaceAptitude/CourseFeatures マージ
  + 別途 HorseHistory/JockeyContext/TrainerContext/JockeyTrainerCombo 計算
  → RacePredictor.predict(single, hist, jockey, trainer, jt)

目標 (各関数 5行):
  FeatureBuilder.build_for_training()
  + _apply_jra_filter()
  → RacePredictor.predict(single, None, None, None, None)
```

**关键点:**
- FeatureBuilder._build_base_features() → FeatureEngine.build_all() → Group B で BloodlineFeatures を含む全基礎特徴量を生成
- FeatureBuilder._enrich_features() → 13モジュール (HorseHistory/JockeyContext/TrainerContext/JockeyTrainerCombo 含む) を feat_df にマージ
- RacePredictor.predict() は hist_features=None の場合マージをスキップ (race_predictor.py L252-253)。jockey/trainer/jt も同様
- BacktestEngine では jockey_groups/trainer_groups/jt_groups を空 dict にして verify 済み (engine.py L1000-1002)

### _run_diagnose の追加修正

_run_diagnose は現在 BloodlineFeatures を含んでいない (L898-954 に blood_* マージなし)。
FeatureBuilder による置換で同時に修正される。これは追加バグの無害化。

### GAP-2: BloodlineFeatures ドキュメント

_enrich_features() docstring の「13 エンリッチメントモジュール」を「14 エンリッチメントモジュール」に修正し、BloodlineFeatures が FeatureEngine.build_all() Group B で実行される旨をコメントに明記。

### Task 1: _build_features_fb() ヘルパー抽出

**File:** `scripts/run_paper_trading.py`
**What:** `_apply_jra_filter()` の直後に新しいヘルパー関数を追加。

```python
def _build_features_fb(
    store: "ParquetStore",
    race_df: pd.DataFrame,
    entry_df: pd.DataFrame,
    odds_df: pd.DataFrame,
    odds_ts_df: pd.DataFrame | None = None,
    **kwargs: Any,
) -> pd.DataFrame:
    """FeatureBuilder で特徴量を一括生成し JRA フィルタを適用 (GAP-1 closure).

    BacktestEngine.run() L946-995 と同一の FeatureBuilder.build_for_training() パス。
    BloodlineFeatures は FeatureEngine.build_all() Group B で含まれる。
    **kwargs は build_for_training() に転送 (preserve_columns 等)。
    """
    from features.feature_builder import FeatureBuilder

    builder = FeatureBuilder(store=store)
    result = builder.build_for_training(
        race_df, entry_df, odds_df, odds_ts_df=odds_ts_df, **kwargs,
    )
    feat_df = result.frame
    feat_df = _apply_jra_filter(feat_df)
    return feat_df
```

**Done when:**
- ヘルパーが `preserve_columns` 等の kwargs を `build_for_training()` に転送する
- ruff check 通過
- 関数が `_run_predict`/`_run_diagnose`/`_run_dry_run` のスコープ内からアクセス可能
